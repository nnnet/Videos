# F3 `harvest-ritual` — отчёт об исполнении

Дата: 2026-09-19. Узел F3 плана `2026-09-19T00-10__claude-global-env-foundation.md`.

## Что создано

| Артефакт | Что это |
|---|---|
| `~/.agent-ops/bin/agent-harvest` | ритуал сбора кандидатов, 20 КБ, `+x` |
| `~/.agent-ops/harvest-tombstones.tsv` | тумбстоуны (создаётся при первом `--dismiss`) |
| `~/.agent-ops/.harvest-last` | key→текст последнего прогона, для читаемых тумбстоунов |
| `~/.agent-ops/.harvest-errstamp` | штамп «об этой поломке сегодня уже сказали» |
| `~/.claude/settings.json` | третий хук в массиве `Stop` |
| `~/.agent-ops-backups/settings.json.bak-F3` | полный бэкап до правки |

Режимы: `agent-harvest` (≤5 строк), `--show` (полный), `--hook` (JSON с
`systemMessage`), `--dismiss KEY...`, `--tombstones`.

Источники — все три проверены `--help`-ом, существуют и так называются:
`repowise decision candidates --format json`, `repowise corrections --format json`,
`agent-q -p gate-failures --json`.

## Решения по ходу

**Тумбстоуны разведены по двум местам — сознательно, а не по недосмотру.**
У решений тумбстоуны уже есть в самом repowise: `decision dismiss` хранит
отклонённое и «never re-proposed». Свой слой поверх дал бы два независимых
выключателя, и отклонённое в одном месте всплывало бы из другого — поэтому
`--dismiss d:...` отказывается работать и печатает родную команду.
У `corrections` и `gate-failures` тумбстоунов в апстриме нет: это проекции,
пересчитываемые из транскриптов и журнала на каждый прогон, они предлагали бы
одно и то же вечно. Для них — `harvest-tombstones.tsv`.

Ключ — sha1 от полей содержания, **счётчик повторов в отпечаток не входит**:
он растёт между сессиями, и отпечаток со счётчиком протухал бы ровно тогда,
когда промах повторился — то есть когда молчание и нужно.

**Порог «повторяемости» берётся из самого отчёта** (`min_count` в JSON
corrections), а не выдумывается: показываем ровно то, что `--write` признал бы
повторяющимся. Разовая опечатка — не промах.

**Провалы гейта фильтруются по проекту сессии**; проекция общая по всем
проектам, сессия — про один. Имя проекта берётся из `registry.tsv`, а не из
basename каталога (иначе `video-wizard`/`video_wizard` разъедутся).

**Канал вывода в хуке — `systemMessage`.** У `Stop` stdout в контекст не
попадает (в отличие от `SessionStart`, где stdout = additionalContext).
`decision`/`block` не выставляется: блокировать остановку сессии ради отчёта
недопустимо. Дубль в stderr — на случай, если `systemMessage` в этой версии
CLI не отрисуется; молчащий ритуал бесполезен.

**Ошибки при нуле находок — одна строка в сутки.** Правило «нечего собирать →
ноль строк» соблюдается, но сломанный источник молчал бы вечно и выглядел как
«всё чисто». Компромисс: при `total == 0` ошибка сообщается не чаще раза в
день и ровно одной строкой (штамп в `.harvest-errstamp`).

## Приёмка — реальный вывод

**Полная загрузка — ровно 5 строк:**
```
harvest[videos]: решений 3 · промахов 2 · гейтов 2 → agent-harvest --show
  реш d:a1b2c3d4 Журнал событий — по одному sqlite на проект, а не общий
  пром c:336883 x4 sudo /run/timeshift/*/backup/ → /tmp/btrfs-root/
  гейт g:09c2bf x5 REQ-004: требование без сценария
  → repowise decision confirm a1b2c3d4… · agent-harvest --dismiss <key>
```
По одному из каждого источника: источник не вытесняется соседом, у которого
просто больше находок. Промах со `count:1` отфильтрован, гейт чужого проекта
(`viralmint`) отфильтрован, готовый к `confirm` кандидат (пустые `blockers`)
поднят наверх.

**Нечего собирать (реальное состояние) — ноль строк:**
```
rc=0 lines=0            # обычный режим
rc=0 stdout_bytes=0 stderr_bytes=0   # --hook
```
Состояние настоящее: кандидатов нет ни в одном из 5 активных проектов реестра,
`gate-failures` пуста (узел D4 ещё не наполнил `gate.*`), единственный
correction имеет `count:1` при `min_count:2`.

**Недоступный источник — не падает, rc=0:**
```
$ HARVEST_REPOWISE=/nope/repowise agent-harvest
harvest[videos]: гейтов 2 → agent-harvest --show
  ! repowise decision candidates: недоступен (rc=127)
  ! repowise corrections: недоступен (rc=127)
  гейт g:09c2bf x5 REQ-004: требование без сценария
  → agent-harvest --dismiss <key>
rc=0
```
Ошибки занимают слоты **первыми**: отчёт, часть источников которого не
ответила, обязан сказать об этом раньше, чем показывать находки — иначе он
тихо врёт про полноту.

**Все источники сломаны, находок 0 — одна строка, и только раз в сутки:**
```
harvest[videos]: источник недоступен — repowise decision candidates: недоступен (rc=127)
rc=0  (1-й прогон)
      (2-й прогон — тишина)
rc=0
```

**Тумбстоуны:**
```
$ agent-harvest --dismiss c:336883 g:09c2bf d:a1b2c3d4
отклонено: c:336883  sudo /run/timeshift/*/backup/ → /tmp/btrfs-root/
отклонено: g:09c2bf
agent-harvest: d:a1b2c3d4 — решение; у repowise свои тумбстоуны: repowise decision dismiss <full-id>

$ cat harvest-tombstones.tsv
# agent-harvest: отклонённое. key	дата	что это было. Удалить строку = предлагать снова.
c:336883	2026-09-19	sudo /run/timeshift/*/backup/ → /tmp/btrfs-root/
```
Следующий прогон: `промахов 2 → 1`, `гейтов 2 → 1`, отклонённое не всплывает.

## Замер времени (критический путь завершения сессии)

| Сценарий | Было | Стало |
|---|---|---|
| реальный прогон (живые источники), 3 замера | — | **0.52 / 0.53 / 0.52 с** |
| E2E ровно той строкой, что в `settings.json` | — | **0.525 с** |
| рендер при полной загрузке (заглушки) | — | 0.040 с |
| **два зависших источника** | **8.04 с** | **4.03 с** |

Найдено приёмкой и исправлено: при последовательном сборе два зависших
источника давали **8 с на выходе из сессии**, и живой третий источник при этом
терял свои находки — бюджет заканчивался до него. Источники независимы и
только читают, поэтому запускаются параллельно: потолок стал равен таймауту
одного вызова, а не сумме, и находки живого источника переживают зависание
соседей (в T8' гейты на месте при двух таймаутах).

Вторая находка приёмки: `local rc=$?` внутри `if ! cmd; then` равен статусу
инверсии, то есть нулю — код ошибки терялся. Снимается отдельной строкой.

## settings.json

Бэкап `~/.agent-ops-backups/settings.json.bak-F3` снят до правки, sha256
совпал с оригиналом. Правка программная (python3 json), атомарная (mkstemp +
`os.replace`, права скопированы), идемпотентная (повторный прогон: «уже
подключён — файл не тронут»). Содержимое файла и значения ключей нигде не
печатались.

Сверка до/после — ни одно событие не потеряло хуков:

| PostToolUse | 3 | 3 |
| PostToolUseFailure | 2 | 2 |
| PreCompact | 1 | 1 |
| PreToolUse | 5 | 5 |
| SessionStart | 5 | 5 |
| **Stop** | **2** | **3** |

`Stop` = `['stop-detect-compact.sh', 'agent-emit', 'agent-harvest --hook']` —
прежние два на месте и первыми. Семантический diff с бэкапом: после удаления
добавленного матчера структура **побайтово-семантически идентична** бэкапу
(`cur == bak` → True). Ключей верхнего уровня 25 → 25. Отступ взят из самого
файла, чтобы правка не переформатировала его целиком.

## Что осталось нерешённым

1. **Схема кандидатов проверена по исходнику, а не на живых данных.** Ни в
   одном из 5 активных проектов реестра нет ни одного кандидата
   (`{"candidates":[],"count":0}` везде), поэтому рендер решений проверен на
   заглушке, собранной по фактическому коду
   `repowise/cli/commands/decision_review_cmd.py:154-167` (поля `id`, `title`,
   `source`, `confidence`, `review_state`, `needs_split`, `lane`, `blockers`).
   Первый же настоящий кандидат — повод перепроверить вывод глазами.
2. **`gate-failures` пуста до узла D4.** Третий источник вхолостую до тех пор,
   пока `agent-ops spec-check` не начнёт писать события `gate.*`. Фильтр по
   проекту и рендер проверены заглушкой с реалистичными строками проекции.
3. **`systemMessage` для `Stop` не проверен вживую** — для этого нужен реальный
   выход из сессии Claude Code, изнутри агента не воспроизводится. Страховка:
   дубль в stderr. Если при первом настоящем выходе из сессии отчёт не
   появится — смотреть сюда.
4. **0.52 с на каждом выходе из сессии** — это почти целиком холодный старт
   двух процессов `repowise` (python). Если станет мешать, дешёвый ход —
   запускать harvest не на каждом `Stop`, а не чаще раза в N минут (штамп,
   как у `.harvest-errstamp`).
5. **Гонка за `settings.json` с параллельными агентами.** Правка атомарная, но
   агент, читавший файл до неё и пишущий после, затрёт хук. Финальная сверка
   после всех правок показала `Stop: 3` — на момент завершения узла цел.
6. **Открытый хвост G4** (соглашение `post-commit.local` не записано в
   `docs/operations/runbook.md`) этим узлом **не закрыт** — F3 делает механизм
   пополнения дерева, а не само наполнение.

Коммит и правка файла плана — за оркестратором, как и предписано заданием.

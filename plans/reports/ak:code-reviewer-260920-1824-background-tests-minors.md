## Находки

### 1. [minor] Повтор записи обречён на тот же провал — `RUNNING` остаётся, гейт молчит
`scripts/test-bg.sh:37-40`. Повтор идёт через тот же `write_verdict`, т.е. тот же
`tmp`-файл в том же каталоге. Для единственной реалистичной причины (каталог
недоступен / ro-fs / ENOSPC) повтор гарантированно падает. Факт из последнего
прогона (`.claude/state/bdd/final-ro.out` + вердикт):

```
TESTS REFUSED: вердикт не записан
TESTS REFUSED: вердикт не записан
TESTS REFUSED: вердикт PASS rc=0 не записан, RUNNING остался
→ test-result.json: {"status":"RUNNING","rc":null,…}
```

Т.е. исходный минор (гейт молчит на `RUNNING`, провал теряется) закрыт только
строкой в stdout. Ветка `TESTS FAIL rc=2` практически недостижима.

Фикс: в запасном пути писать **в существующий файл напрямую**, без `tmp`+`mv` —
это работает и в каталоге без права записи (проверил экспериментом:
`echo … > ro-dir/file` → OK, права каталога для перезаписи существующего файла
не нужны):

```bash
if ! write_verdict "$s" "$rc"; then
  jq -nc --arg s FAIL --argjson rc 2 --arg l "$ST/test-result.log" \
     --arg ts "$(date -Is)" --arg cwd "$ROOT" \
     '{status:$s, rc:$rc, log:$l, ts:$ts, cwd:$cwd, acked:false}' >"$ST/test-result.json" \
    && { echo "TESTS FAIL rc=2 (вердикт $s rc=$rc не записан)"; exit 2; }
  echo "TESTS REFUSED: вердикт $s rc=$rc не записан, RUNNING остался"; exit 2
fi
```

Цена — неатомарность последней попытки; гейт fail-open (битый JSON → `exit 0`),
так что рваный файл не опаснее нынешнего `RUNNING`. Зато сценарий `final-ro`
начинает проверять реальную ветку `FAIL rc=2`, а не только REFUSED.

### 2. [minor] Каталог недоступен *с самого начала* → `TESTS BUSY` rc=3 вместо `REFUSED` rc=2
`scripts/test-bg.sh:22-23`. Проверил на чистом ro-каталоге:

```
line 22: …/test-bg.lock: Permission denied
flock: 9: Bad file descriptor
TESTS BUSY: прогон уже идёт      → rc=3
```

Проза REQ-001 («…или ошибка записи вердикта до старта → `TESTS REFUSED`, код 2»)
обещает другое, а агент по `BUSY` решит, что идёт чужой прогон, и будет ждать
фантом. Новый сценарий `ro` (feature:67) это маскирует: он предварительно делает
успешный прогон, поэтому `test-bg.lock` уже существует и `exec 9>` проходит.
Расхождение досталось по наследству (лок был и до изменения), но требование
правит именно это изменение.

Фикс — после `mkdir -p "$ST"; ST=$(cd "$ST" && pwd)` (scripts/test-bg.sh:21):
```bash
[ -w "$ST" ] || { echo "TESTS REFUSED: каталог $ST недоступен для записи"; exit 2; }
```
и в сценарий `ro` добавить второй прогон в каталог без `test-bg.lock`.

### 3. [minor] `TESTS REFUSED` печатается и на путях, которые кончаются не отказом
`scripts/test-bg.sh:30` (`write_verdict`) всегда echo-ит `TESTS REFUSED: вердикт не
записан`. Следствия: (а) в отказном пути три «REFUSED»-строки подряд — шум
терпимый; (б) **строка `TESTS REFUSED` перестаёт быть признаком статуса**: если
повтор из finding 1 удастся, stdout будет `TESTS REFUSED…` + `TESTS FAIL rc=2…`;
(в) сценарий `final-ro` из-за этого пройдёт **в обеих** ветках, т.е. ничего про
исход не доказывает. Фикс: `write_verdict` делает молча `return 1` (или пишет
`verdict-write-error: …` в stderr), единственную строку `TESTS …` печатает
вызывающий код.

### 4. [minor] Заголовок сценария противоречит своим же THEN

(«Провал финальной записи не оставляет RUNNING молча»), либо покрыть ветку
реально — она станет достижимой после finding 1.

### 5. [nit] Ветка `FAIL rc=2` не печатает хвост лога
`scripts/test-bg.sh:39` — `exit 2` минуя `tail -n 40`, хотя требование описывает
stdout как «`TESTS <status> rc=<n>` и хвост лога». Дёшево поправить.

### 6. [nit] Сценарий «Под pytest без TEST_STATE_DIR» зависит от окружения
`bdd/features/background-tests.feature:89` — `TEST_CMD=true scripts/test-bg.sh`
наследует внешний `TEST_STATE_DIR`, поэтому при рекомендованном для ревью запуске
(`TEST_STATE_DIR=.claude/state/bdd/review pytest …`) сценарий падает: обёртка
честно пишет в review-каталог и отдаёт `TESTS PASS rc=0`. Фикс — герметизировать:
`env -u TEST_STATE_DIR TEST_CMD=true scripts/test-bg.sh`.

### 7. [nit] Права восстанавливаются не в исходные
`chmod a-w` → `chmod u+w` даёт 755 вместо умолчательных 775 (видно на
`.claude/state/bdd/ro`, `final-ro`). Функционально безразлично (один владелец).
Заодно: при жёстком прерывании между `chmod a-w` и восстановлением ручная уборка
`rm -rf .claude/state/bdd` споткнётся о ro-каталог (следующий прогон чинит сам —
`chmod u+w` в прологе). Если важно — `chmod u+w` в обоих сценариях можно заменить
на `chmod 775`.

### 8. [nit] Тайминги BUSY — приемлемы
`cp` вердикта на t≈1 с при `sleep 3` и `cmp` до `wait`: запас ~2 с, второй запуск
до `BUSY` делает только `mkdir -p` и усечение лока — вердикт не трогает, так что
`verdict-same=1` действительно доказывает «ни байта». Любой перекос (медленная
запись `RUNNING`) даёт громкое падение, а не ложный проход.

# background-tests — фоновый прогон тестов с реакцией по хуку

## Why

Сейчас агент запускает `pytest` и ждёт его в основном ходе: длинный или
зависший прогон блокирует работу, а исход прогона агент проверяет сам и
может «не заметить» красный результат. Нужно, чтобы (а) прогон шёл в фоне и
агент продолжал работу, (б) о завершении, провале и зависании агенту сообщал
harness/хук, (в) необработанный провал не давал закончить ход молча.

Штатные механизмы Claude Code 2.1.267 (docs `hooks`, `tools-reference`; описание
инструмента Bash в системном промпте) покрывают всё это без внешних демонов:

- `Bash` c `run_in_background: true` — по описанию инструмента harness «re-invokes
  you when it exits»; в docs явной формулировки нет — проверяется задачей 1.
- Параметр `timeout` инструмента Bash **не** ловит зависание: по таймауту
  команда просто уезжает в фон. Watchdog обязан жить в обёртке (`timeout`).
- Stop-хук получает `background_tasks[]` и может отличить «тесты ещё бегут»
  от «провал не обработан»; ответ `{"decision":"block","reason":…}` не даёт
  закончить ход (защита: `stop_hook_active`, лимит 8 блоков подряд).

## What Changes

- **Обёртка `scripts/test-bg.sh`** — запускает набор тестов под `timeout`,
  пишет вердикт `PASS | FAIL | HANG` в `.claude/state/test-result.json`
  (+ полный лог в `.claude/state/test-result.log`), печатает
  `TESTS <status> rc=<n>` и хвост лога, возвращает код тестов.
- **Stop-гейт `scripts/test-gate.sh`** — хук события `Stop`: если есть
  необработанный `FAIL`/`HANG` и тесты не бегут — блокирует завершение хода
  с инструкцией (что прочитать, что сделать, как квитировать); harness снимает
  блок после 8 подряд — документированный потолок. Во всех остальных случаях
  (PASS, квитировано, устарело, тесты ещё бегут, идёт авто-компакт) молчит. Никогда не ломает сессию: любая внутренняя
  ошибка → exit 0.
- **Регистрация** гейта в `.claude/settings.json` (`hooks.Stop`, точечный merge).
- **Два bdd-шага** в `bdd/steps/repo_steps.py` (`завершается с ошибкой`, `файл содержит`).
- **Правило в `CLAUDE.md`**: тесты запускаются **только по решению агента**,
  только через `scripts/test-bg.sh` с `run_in_background: true`, без
  ожидания; реакция на уведомление — по статусу.

## Non-goals

- **Автозапуск тестов на `Edit|Write`** (PostToolUse + `asyncRewake`) —
  отвергнут пользователем: «тесты только по решению Клода».
- Изменение самого набора тестов / `bdd/pytest.ini`.
- Глобальные хуки `~/.claude/settings.json` — не трогаем (апстрим-правило).
- Хук в `.claude/hooks/` — каталог закрыт песочницей (deny-mount); скрипт
  живёт в `scripts/`, что не меняет поведение и снимает обход песочницы.

## Capabilities

- `background-tests` (новая): фоновый прогон тестов, вердикт, Stop-гейт,
  правило запуска.

## Impact

- Новые файлы: `scripts/test-bg.sh`, `scripts/test-gate.sh`,
  `bdd/features/background-tests.feature`.
- Изменяемые: `.claude/settings.json` (секция `hooks`), `CLAUDE.md`
  (раздел о тестах), `bdd/steps/repo_steps.py` (2 шага), `.git/info/exclude`
  (`.claude/state/`).
- Зависимости: `bash`, `coreutils timeout`, `jq` (есть: `/usr/bin/jq`).
- Риски (по аудиту 2026-09-20): устаревший/чужой вердикт — TTL + `acked` +
  поля `ts`/`cwd`; завершённая задача в `background_tasks` — проверка
  `status`; конфликт с глобальным авто-компакт Stop-хуком — маркер в
  `last_assistant_message`; прогон сценариев затирает вердикт — обязательный
  `TEST_STATE_DIR`.

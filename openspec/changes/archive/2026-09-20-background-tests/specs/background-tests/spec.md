# background-tests Specification

## Purpose
Фоновый прогон тестов по решению агента: обёртка фиксирует вердикт,
harness будит агента по завершении, Stop-гейт не даёт молча закончить ход
с необработанным провалом или зависанием.

## ADDED Requirements

### Requirement: REQ-background-tests-001 Обёртка фиксирует вердикт прогона
Обёртка `scripts/test-bg.sh` SHALL запускать набор тестов проекта под
сторожевым таймером (`TEST_TIMEOUT`, по умолчанию 600 с) и по завершении
атомарно записывать вердикт в `<state>/test-result.json` с полями `status`
(`PASS` | `FAIL` | `HANG`), `rc`, `log`, `ts`, `cwd`, `acked: false`, полный
вывод — в `<state>/test-result.log`, а в stdout печатать строку
`TESTS <status> rc=<n>` и хвост лога. Код возврата обёртки SHALL равняться
коду прогона. `<state>` по умолчанию — `.claude/state` в корне репозитория,
вычисленном от расположения скрипта (не от cwd и не от переменных окружения
хуков). Команда и каталог переопределяются `TEST_CMD`, `TEST_STATE_DIR`.
Второй одновременный запуск SHALL завершаться сразу с сообщением, не трогая
вердикт. Под pytest (`PYTEST_CURRENT_TEST` задан) без `TEST_STATE_DIR` обёртка
SHALL отказываться писать в каталог по умолчанию — иначе прогон сценариев
затёр бы настоящий вердикт.

#### Scenario: Зелёный прогон даёт PASS
- **WHEN** обёртка запущена с `TEST_STATE_DIR` во временный каталог и
  командой, завершающейся кодом 0
- **THEN** команда завершается успешно
- **AND** вывод содержит `TESTS PASS rc=0`
- **AND** файл вердикта содержит `"status":"PASS"` и `"acked":false`

#### Scenario: Красный прогон даёт FAIL
- **WHEN** обёртка запущена с `TEST_STATE_DIR` во временный каталог и
  командой, завершающейся кодом 1
- **THEN** команда завершается с ошибкой
- **AND** вывод содержит `TESTS FAIL rc=1`
- **AND** файл вердикта содержит `"status":"FAIL"`

#### Scenario: Превышение таймера даёт HANG
- **WHEN** обёртка запущена с `TEST_STATE_DIR` во временный каталог,
  `TEST_TIMEOUT=1` и командой, работающей дольше
- **THEN** вывод содержит `TESTS HANG rc=124`
- **AND** файл вердикта содержит `"status":"HANG"`

#### Scenario: Под pytest без TEST_STATE_DIR обёртка отказывается писать
- **WHEN** обёртка запущена из-под pytest без `TEST_STATE_DIR`
- **THEN** команда завершается с ошибкой
- **AND** вывод содержит `TEST_STATE_DIR`

### Requirement: REQ-background-tests-002 Stop-гейт не даёт закончить ход с необработанным провалом
Хук `scripts/test-gate.sh` на событии `Stop` SHALL читать JSON события из
stdin и вердикт из `<state>/test-result.json` (тот же `<state>`, что у
обёртки). Он SHALL вывести ровно один JSON-объект
`{"decision":"block","reason":…}` — reason содержит статус, код, путь к логу и
инструкцию (FAIL → найти причину, исправить, перезапустить обёртку в фоне;
HANG → найти зависший шаг по логу, таймер молча не поднимать, помнить что
rc=137 может быть внешним kill; если исправить нельзя — квитировать точной
командой из reason и объяснить пользователю) — тогда и только тогда, когда
одновременно:
- вердикт есть, читается и не старше `TEST_RESULT_TTL_MIN` (по умолчанию 240 мин);
- `status` ∈ {`FAIL`, `HANG`} и `acked` = `false`;
- в `background_tasks[]` нет задачи с `type` = `shell`, командой, содержащей
  `scripts/test-bg.sh`, и статусом, означающим выполнение (`running`,
  `pending`, `queued`, `in_progress` или отсутствующий `status`);
- `last_assistant_message` не содержит маркера авто-компакта
  `AUTO-COMPACT-READY` (иначе гейт сорвал бы глобальный цикл компакта).

Во всех остальных случаях, а также при любой внутренней ошибке (нет `jq`,
пустой или битый stdin, битый вердикт) хук SHALL завершиться кодом 0 без
вывода. Хук SHALL NOT завершаться кодом 2. Harness прекращает блокировку после
8 подряд — это документированный потолок, а не дефект.

#### Scenario: Необработанный FAIL блокирует завершение хода
- **WHEN** вердикт `FAIL`, `acked` = `false`, и в событии Stop нет фоновых задач
- **THEN** вывод содержит `"decision":"block"`
- **AND** вывод содержит `FAIL` и путь к логу

#### Scenario: Тесты ещё бегут — хук молчит
- **WHEN** вердикт `FAIL`, но в `background_tasks` есть задача `type` =
  `shell`, `status` = `running` с командой `scripts/test-bg.sh`
- **THEN** вывод содержит `rc=0 len=0` (код 0, вывод пуст)

#### Scenario: Завершённая задача в списке не глушит гейт
- **WHEN** вердикт `FAIL` и в `background_tasks` та же задача со
  `status` = `completed`
- **THEN** вывод содержит `"decision":"block"`

#### Scenario: PASS, квитированный, устаревший или отсутствующий вердикт — хук молчит
- **WHEN** вердикт `PASS`; или `acked` = `true`; или файла вердикта нет; или
  файл старше TTL; или stdin пуст
- **THEN** вывод содержит `rc=0 len=0`

#### Scenario: Маркер авто-компакта — хук молчит
- **WHEN** вердикт `FAIL`, а `last_assistant_message` содержит `AUTO-COMPACT-READY`
- **THEN** вывод содержит `rc=0 len=0`

### Requirement: REQ-background-tests-003 Тесты запускаются только по решению агента
Проект SHALL регистрировать `scripts/test-gate.sh` как хук `Stop` в
`.claude/settings.json` (точечное добавление ключа `hooks`, остальное
содержимое файла не меняется и не печатается), и SHALL описывать в
`CLAUDE.md` правило: тесты запускает только главный агент по своему решению,
только через `scripts/test-bg.sh` с `run_in_background: true`, без ожидания
окончания; субагенты и `claude -p` тесты в фоне не запускают (harness
убивает фон по их финальному ответу); реакция — по уведомлению
`PASS`/`FAIL`/`HANG`. Настройки проекта SHALL NOT содержать хуков,
запускающих тесты автоматически (например, `PostToolUse` на `Edit|Write`).

#### Scenario: Гейт зарегистрирован, автозапуска нет
- **WHEN** выполняется `jq` по `.hooks` из `.claude/settings.json`
- **THEN** среди команд `hooks.Stop` есть содержащая `scripts/test-gate.sh`
- **AND** ни одна команда `hooks.PostToolUse` не содержит `test-bg`

#### Scenario: Правило записано в CLAUDE.md
- **WHEN** агент читает `CLAUDE.md`
- **THEN** файл содержит `scripts/test-bg.sh` и `run_in_background`

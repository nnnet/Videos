# design — background-tests-hardening

| Решение | Выбор | Почему |
|---|---|---|
| RUNNING до старта | `write_verdict RUNNING null` перед `timeout` | старый FAIL/PASS не должен переживать старт; защита не зависит от формы `background_tasks` |
| Статусы задач | `background_tasks` не разбирается | любой список статусов — угадывание: белый список ложно блокирует, чёрный (`success`, `finished`) ложно молчит навсегда; `RUNNING` закрывает случай без него |
| Дамп события | под `TEST_GATE_DEBUG=1` | остаток диагностики задачи 1; в проде — лишняя запись каждый ход |
| `TEST_STATE_DIR` | оба скрипта `cd $ROOT` до резолва | одинаковый файл вердикта для обёртки и гейта |
| `TEST_TIMEOUT` | `[1-9][0-9]*` иначе REFUSED rc=2 | rc=125 от `timeout` — не провал тестов |
| `stop_hook_active` | по-прежнему не учитывается | блок повторяется до PASS/ack; потолок 8 — документирован |
